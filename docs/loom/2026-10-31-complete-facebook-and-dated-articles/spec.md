## Requirements
REQ-1 — Complete specified Facebook post
  WHEN the researched Facebook post is processed, the scraper shall obtain its complete target body with original paragraphs, hashtags, bullet symbols, body links and target-owned images while excluding comments, other posts and login controls → Acceptance #1

REQ-2 — Complete dated article
  WHEN the researched Felix article is processed, the scraper shall obtain its complete original body in order with its four section headings, body links and image while excluding subscription forms and navigation text → Acceptance #2

REQ-3 — Reject incorrect or incomplete content without damaging notes
  IF target identity is mismatched, the body is truncated, source representations conflict, or only a login, verification or error page is available THEN the scraper shall report extraction failure without saving or summarizing that content as a successful article and shall preserve existing body and summary files on extraction failure → Acceptance #3

REQ-4 — Distinguishable extraction failures
  WHEN extraction of an in-scope page fails, the scraper shall report whether page loading failed, target identity could not be confirmed, body parsing failed, or body completeness could not be confirmed through the existing item-error reporting → Acceptance #4

REQ-5 — Preserve established extraction behavior
  WHEN existing X specified posts and long articles, ordinary articles or configured paginated articles are processed, the scraper shall preserve their successful extraction and existing browser-mode selection, headed retry and headed_on_block effects → Acceptance #5

REQ-6 — Source-backed verification
  WHEN this change is verified, the acceptance report shall state the per-sample comparison of actual source and delivered body for prose order, sections, links, hashtags, symbols and target-owned images rather than inferring completeness from nonempty output or a success status → Acceptance #6

## Design decision
- agent-decided — Correctness is pinned by all three PRINCIPLES.md non-negotiables and the confirmed intent: missing or conflicting ownership/completeness evidence is a failure, not permission to use the longest visible text, a generic social-page fallback, or the first parse that returns content.
- agent-decided — Dispatch supported Facebook post pages before the metadata-only video rejection, leaving the existing YouTube/Bilibili behavior and actual unsupported-video rejection intact; this sample is a text-and-image post despite og:type=video.other.
- agent-decided — Initially support the observed HTTPS Facebook numeric post identity in the original slugged URL and its shorter /fatality1117/posts/10234719952645505/ form through the same identity rules; unknown Facebook layouts or unresolvable post identities fail explicitly rather than entering an unverified generic extractor. Host aliases or other post URL forms are supported only when their requested identity can be verified under those rules; they are not guessed from display text.
- agent-decided — Bind Facebook original message data, author and attached media to the requested post ID using existing page-delivered public fields, and corroborate against exactly one target-owned message region. Ignore non-target records and comments; reject contradictory target records, ambiguous owned bodies, explicit truncation, incomplete attachment extent, or unavailable target body. The requested URL's host and identity remain authoritative over unrelated metadata or redirects.
- agent-decided — Read structured page data as bounded JSON, never execute script contents, issue extra platform API calls or traverse arbitrary account stores. Retain only allowlisted target-post public fields; never persist cookies, authentication/session objects or raw application payloads. This uses the already-loaded source, not a new account or external extraction service.
- agent-decided — Preserve original Facebook message paragraphs and line breaks, all six source hashtags and all 18 emoji-image bullet glyphs; converting the whole visible page, dropping emoji images without their alt text, and applying generic tag cleanup would lose measured source content. Resolve body references from target-owned source evidence and include only verified target-owned image attachments, not author avatars, reaction icons or comment images.
- agent-decided — Preserve substantial dated article bodies on a document copy before parsing, retaining normal cleanup elsewhere; the observed content gh-content container has data-date=2026-10-13 and contains the entire Felix body. Qualifying bodies must be owned by the article rather than an arbitrary dated comments/sidebar container. Retain the original page for independent comparison and require retained visible authored content, heading order, references and images for the protected body; ambiguous bodies or missing units fail rather than silently succeeding.
- agent-decided — Native metadata/body agreement and transport hashes are consistency checks, not proof of an author's unpublished or server-withheld text. No universal completeness guarantee is introduced. The runtime checks reject known incomplete/conflicting representations; independent acceptance compares the actual available target source against the output.
- agent-decided — Integrate validation before the existing content write and summarization boundary, and require fresh extraction for unverified in-scope Facebook and Felix content-only caches rather than resuming a summary from arbitrary historical Markdown. Completed-summary skip behavior and unrelated ordinary-article resume behavior remain as configured; extraction failures must not rewrite earlier notes. ## Alternatives considered
- Merely remove the metadata video guard: rejected because the generic Facebook parse loses all six hashtags and does not establish target ownership/completeness.
- Disable exact-selector cleanup globally: rejected because the measured Felix output then includes player/navigation and subscription interface text, growing to 15,318 characters without establishing correctness.
- Directly convert independently identified body regions for both platforms: workable on the measured samples, but not selected as the only path because it discards useful ordinary-article cleanup and makes hidden page-interface filtering an additional maintenance responsibility; use owned-source conversion where needed for Facebook and retain the parser for dated ordinary articles.
- Only fix Felix: smaller, but omits the confirmed Facebook acceptance condition.
- Add multiple parser engines, a paid API, automatic login or a new browser profile workflow: rejected as unnecessary for the publicly readable sample bodies and outside the confirmed scope.
- Treat historical cache presence, matching hashes, matching character counts or missing visible Show more controls as independent proof of completeness: rejected because each can agree on a partial or wrong body.

## UI flows
| Case | What the user does | What they see |
|---|---|---|
| Successful extraction | Run rlss url <sample-url> --no-summary | The output article contains that target's complete body, original sections where present, references and owned images; the report counts Success: 1 and Failed: 0, and the command exits 0. |
| Summary enabled | Process a verified complete body with the existing summary settings | The existing summary flow uses that body; a later summary failure remains Partial with the valid body preserved. |
| In progress and retry | Start extraction using the existing browser settings | Existing processing messages remain; a failed headless attempt can open the existing visible-browser retry, and success is reported only after the returned body passes the same checks. An explicit visible-browser invocation is not retried again. |
| Verification page | Process a source that serves a recognized verification page | The item fails if no verified body is obtained; headed_on_block:false prevents the blocked attempt from opening a visible retry, while enabling it allows the existing retry. No verification text is saved as an article. Retry after source access is restored. |
| Loading failure | Run the single-URL command when the page cannot load within the existing timeout | The error includes Article load failed and the underlying cause, the report counts Failed: 1, and the command exits 1 after the configured retry is exhausted. Existing notes remain intact; retry when the page is reachable. |
| Target unavailable or wrong | Run the single-URL command when the requested post/article cannot be uniquely identified or navigation delivers another target | The error includes Article target unverified, the report counts Failed: 1, and the command exits 1. Existing notes remain intact; confirm the requested URL and retry once the correct source is accessible. |
| Body unavailable | Run the single-URL command when the identified target has no extractable body or serves only an access/error interface | The error includes Article body unavailable and the cause, the report counts Failed: 1, and the command exits 1. Existing notes remain intact; retry after the actual source body becomes available. |
| Incomplete or conflicting body | Run the single-URL command when source bodies disagree, a preview or attachment is incomplete, or original body units are lost | The error includes Article incomplete, the report counts Failed: 1, and the command exits 1. No partial/wrong body or summary is written over existing notes; retry after complete consistent source content is available. |
| Batch/watch item failure | Continue the existing reading-list run when one item fails | The failed item includes its reason and counts as Failed; later items continue. Existing batch exit behavior and watch retry on the next cycle remain unchanged. |
| Completed and pending notes | Run reading-list processing with completed notes skipped and a pending Facebook or Felix summary present | Completed notes remain Skipped; a pending in-scope body is freshly checked before a summary can use it, and extraction failure preserves the earlier files. Unrelated ordinary-article resume behavior remains unchanged. Running the existing single-URL command still explicitly reprocesses that URL. |
| No work or dry run | Run with no selected items or use the existing dry-run option | Existing no-items or dry-run messages remain, with no new extraction or note writes and unchanged command exit behavior. |
| Development acceptance | Review the acceptance report for the two samples and existing regression cases | Each confirmed acceptance condition has a result, actual-source comparisons and any unavailable or failed sample disclosed; test outputs are isolated from production notes and running processes. |

No new interactive control, bulk note rewrite or data migration is introduced. An unavailable live sample is reported as unavailable/failed, never counted as complete from a cached fixture. The cache clarification enforces the already-confirmed rejection of unverified content and preservation of existing notes.
