# Verify YouTube original audio evidence — spec
intent: 2026-11-01-verify-youtube-original-audio-evidence@88e1abe
confirmed-behavior: 2026-11-01 @680f88f
pre-build-review: required — original-language evidence is ambiguous external data and the extraction-to-cache provenance contract changes

## Requirements
REQ-1 — Verified multi-audio originals
  WHEN processing either collected multi-audio sample (rfscVS0vtbw or aircAruvnKk) with sufficient consistent original-audio evidence and usable subtitles, the scraper shall deliver the original English subtitles → Acceptance #1
REQ-2 — Existing single-audio support
  WHEN processing an existing single-audio video with verified original-language human or automatic subtitles, the scraper shall continue to deliver usable subtitles with accurate language and source labels → Acceptance #2
REQ-3 — Original first, honestly labeled fallback
  WHEN usable verified original-language captions cannot be obtained, the scraper shall permit other valid platform subtitles and normal configured summarization, labeling the actual language, human/automatic source and original-language uncertainty or known translation without claiming verified originality → Acceptance #3
REQ-4 — Preserve target and content validation
  WHEN extracting subtitles, the scraper shall retain target-identity, substantive-text, cue-timing and completeness validation, existing retries and cache safeguards, and shall not report unsuccessful extraction as success → Acceptance #4
REQ-5 — Source-backed live verification
  The verification report shall identify actual video targets, original-language evidence, selected subtitle language and source, and correspondence with downloaded cue text, explicitly distinguishing unavailable live evidence from a successful verification → Acceptance #5

## Design decision
- user-decided — intent Constraints and PRINCIPLES.md Non-negotiables 1–3 pin correctness over coverage. On 2026-11-01 the user revised the language requirement to “以原始語言的字幕優先”: usable original-language subtitles take precedence, but language uncertainty or known translation alone no longer makes extraction unsuccessful. Both human and automatic subtitles are acceptable; target and actual content correctness remain mandatory. No existing notes, settings or logged-in browser state are migrated.
- agent-decided — extend the existing YouTube candidate selector, not the downloader or Defuddle integration. Real captured player metadata for both samples contains a uniquely marked original streaming audio ID that exactly matches one caption-audio association; the current unconditional multi-audio rejection discards this evidence.
- agent-decided — an explicit original marker in first-party streaming audio metadata is evidence only when bound to a valid language-bearing audio ID, exactly one caption-audio association with that ID, and valid associated caption indices. Collect both streaming format lists; collapse repeated formats by exact audio ID, disqualify contradictory original/dubbed declarations for that ID, competing original IDs, malformed associations, or incompatible original-language signals as original-language proof. Such contradictions do not establish originality but do not by themselves prohibit a separately validated fallback caption. Neither a default flag/index, a language-looking ID (including its numeric suffix), nor a display label alone establishes original language. Initially recognize the observed explicit English original suffix; unknown localized labels yield no proof rather than guessed translations. These are platform assertions, not independent audio recognition or a documented permanent YouTube API contract.
- agent-decided — try nontranslated caption candidates of the verified original audio's language family from its bound caption association before fallback candidates. Do not derive the original language from caption ordering or default selection. Conflicting automatic-caption language evidence on that original association must not be silently ignored. Regional variants remain eligible only within the verified language family, preserving existing behavior.
- agent-decided — preserve the current unambiguous single-audio automatic-caption association as fallback evidence when explicit original metadata is absent and no contrary multi-audio/dubbing evidence exists. Invalid explicit claims must not fall through into weaker claims of verified originality. Manual-only samples may succeed through the fallback path, explicitly labeled original language unconfirmed.
- agent-decided — evaluate inline and refreshed native-player data independently. With absent inline proof, a refreshed response may independently establish the original language; it is not required to agree with a nonexistent initial language. Once a family is verified, a later incompatible verified family disqualifies original-language claims from those conflicting responses; their valid captions remain fallback candidates labeled unconfirmed. Contradictory explicit claims within a response never become verified through that response's weaker ASR evidence. Missing refreshed evidence establishes nothing and does not erase consistent earlier proof. Keep existing bounded inline/IOS/ANDROID attempts, strict first-party subtitle endpoint/target rules, redirect refusal, actual XML cue validation and deterministic candidate ordering; unusable human captions may still fall through to usable automatic captions.
- agent-decided — record the evidence actually used in target-bound transcript provenance; metadata-based success must not falsely claim automatic-caption association. Update the Go consumer and tests with the producer. Preserve acceptance of existing valid association evidence and rejection of absent, unknown or inconsistent provenance; no cache migration or newly trusted unmarked cached text. New fallback evidence must be an explicit supported result, with uncertainty visible in saved content; it is not equivalent to absent or unrecognized provenance.
- agent-decided — fallback selection remains deterministic: after all bounded original-language attempts fail, consider validated platform default captions, then remaining available captions in platform order. A known translation endpoint is eligible only in this fallback phase with an explicit translation label, preserving HTTPS/host/path/video binding and XML validation. An endpoint with unknown identity or invalid content is never rescued by language relaxation. Do not generate a new translation request merely because no original proof exists. Defuddle integration remains outside this change; relaxed language policy alone does not require a second downloader.
- agent-decided — for an already supplied translated endpoint, the delivered language is its single nonempty valid `tlang` target, not the source track's languageCode. Reject duplicated, malformed or empty translation targets and conflicts with available declared target metadata. Source human/automatic describes the underlying caption track; saved labels and provenance separately identify platform translation, source language and delivered language. A nontranslated track differing from a verified original family is also labeled known translation; without that proof it is labeled original unconfirmed. Do not synthesize new translation URLs.
- agent-decided — live validation uses isolated logged-out profiles and public source requests only. Keep full downloaded subtitles, signed endpoints and browser artifacts outside Git; commit bounded metadata evidence and outcome summaries only. No new account, paid service, third-party proxy or audio transcription is introduced. Save explicit language status (verified original, original unconfirmed, or known translation); retain actual subtitle language and human/automatic source. A successful fallback may be summarized under the existing provider/settings without a new manual-only stop. Word-for-word audio accuracy and uninterrupted access to YouTube are not promised.

## Alternatives considered
- Keep rejecting all multi-audio videos: smaller but fails the requested improvement despite target-bound evidence in both samples.
- Accept a default or first subtitle as verified original: rejected because it may be a dub or translation. Such tracks may instead be explicitly labeled fallback results after original candidates are exhausted.
- Infer originality from an audio ID numeric suffix alone or from an arbitrary localized label: rejected because these are insufficient independent evidence and risk false positives.
- Replace extraction with Defuddle or add its fallback: outside the confirmed scope; measured transcript availability did not establish equivalent original-language guarantees or a reliable fallback.
- Add audio recognition or a broad locale-label dictionary: unnecessary scope and new maintenance/privacy cost; unknown evidence remains honestly labeled rather than guessed.

## UI flows
| Case | What the user does | What they see |
|---|---|---|
| Verified multi-audio original | Processes either collected video through an existing single-URL, batch or watch command | Valid original English subtitles are saved with language and human/automatic source labels; ordinary summary processing follows current settings. A fully successful single-URL run exits 0. |
| Existing single-audio original | Processes a previously supported human- or automatic-caption video | The original-language transcript and source labels remain available. Empty human captions do not prevent trying usable verified automatic captions. |
| Unknown or conflicting original language | Processes a video lacking consistent original-language proof but having valid target subtitles | Saves usable subtitles, explicitly labels original language unconfirmed and the actual subtitle language/source, and continues normal configured summarization. A fully successful single-URL run exits 0; conflicting evidence is never labeled verified. |
| Only other-language subtitles usable | Processes a video whose verified original-language subtitles are absent or unusable | Uses valid available subtitles after exhausting original-language candidates; labels a known translation as translated, otherwise original language unconfirmed, and continues normal configured summarization. |
| No usable captions | Processes a video with only empty/malformed/incomplete cues or inaccessible subtitles | Existing diagnostics report unavailable or unusable subtitles; no description is saved as a transcript. Single-URL exits nonzero. Retry when usable subtitles or access become available. |
| Wrong target | Processes a page whose player or subtitle endpoint belongs to another video | Extraction fails with existing target/endpoint diagnostics rather than saving another video's text. Retry the correct accessible video URL. |
| In progress | Waits for extraction | Existing progress/log output and bounded requests apply. Existing browser fallback settings, including headed_on_block, retain their current effects. |
| Batch/watch failure and retry | Processes a batch containing an unsuccessful video, or encounters it again later | The failed item is counted as failed and other items continue; existing batch/watch exit behavior is preserved. A later attempt rechecks current evidence rather than converting an earlier failure into success. |
| Cached content or completed summary | Resumes existing work | Existing validated transcript caches remain eligible; unverified cached text is not newly trusted for a pending summary. Existing completed-summary skipping remains; notes are not rewritten as a migration. |
| Empty selection / dry run | Runs an empty batch or dry run | Existing no-items/dry-run output remains; no new subtitle or summary requests occur. |

The existing command entry points, output layout and configuration are retained; no new command, switch or interactive screen is introduced. Stop/rerun uses existing commands and revalidates fresh data; interrupted requests are not success. Existing output-write and summary-provider failures retain their current handling. Offline or inaccessible videos may fail; source availability is not guaranteed. This change does not restart the running program, modify browser login state, or rewrite existing user notes.
