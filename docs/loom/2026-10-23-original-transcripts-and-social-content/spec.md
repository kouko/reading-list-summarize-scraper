# Original transcripts and social content — spec

confirmed-behavior: 2026-10-23 @a7b7c88

## Requirements
REQ-1 — Original-language transcripts
  WHEN processing a supported video, the scraper shall deliver subtitles whose language is supported by evidence of the video's original spoken language, accepting human and platform-generated subtitles but never substituting translations or an unverified default language → Acceptance #1
REQ-2 — Target social article body
  WHEN processing an accessible Threads post, Medium article, or X/Twitter post or long article, the scraper shall extract the target's main text rather than navigation, recommendations, other posts, or replies → Acceptance #2
REQ-3 — Explicit unsuccessful extraction
  IF target content or original-language evidence cannot be obtained, THEN the scraper shall report the item as unsuccessful and avoid saving or summarizing a substitute page, video description alone, login/challenge screen, or detected preview-only article → Acceptance #3
REQ-4 — Validate subtitle contents
  WHEN selecting a subtitle track, the scraper shall examine its actual text and available timing/completeness evidence, reject empty or timestamp-only tracks and malformed or explicitly incomplete payloads, and try another verified original-language track rather than accept a human/automatic label as proof of usability → Acceptance #4

## Design decision
- user-decided — correctness is required; original-language human and automatic subtitles are both acceptable; human provenance alone is not a reason to accept an empty or unusable track. PRINCIPLES.md Non-negotiables 1–3 prohibit substitute-content success.
- agent-decided — use Defuddle 0.19.5 as the reproducible extraction dependency baseline; keep the browser bundle built locally and the existing browser-mode/profile selection and headed_on_block behavior. Updating the dependency alone is not sufficient language or content validation.
- agent-decided — first implement video transcript extraction for YouTube and Bilibili, the upstream video extractors already examined; video URLs recognized outside these supported adapters fail explicitly instead of passing descriptions as transcripts. This does not claim universal video-platform support.
- agent-decided — separate evidence for the original spoken language from the chosen subtitle track's language. Prefer authoritative original-audio metadata; use an unambiguous original-audio automatic-caption association only when it identifies the original recording. Interface language, page language, title, default captions, preferred locale, or the first available track are not independent proof. Ambiguous multilingual/dubbed audio or conflicting evidence fails closed; regional variants may match only within a verified original language family, without translating text.
- agent-decided — fetch eligible original-language candidates and inspect actual cue text before choosing. Empty human subtitles must not prevent trying usable original-language automatic subtitles. Human and automatic candidates use the same validation; do not claim relative transcription accuracy from provenance, text length, or language metadata. If several candidates remain equally supported, use a deterministic platform ordering after validation rather than an unconditional human-first rule.
- agent-decided — validate nonempty substantive cue text, parseable finite/nonnegative cue timing when supplied, valid cue intervals, and explicit incomplete/truncated-response signals. A long silent interval or low duration coverage alone is not proof of missing speech. No audio recognition, audio upload, translation generation, or claim of word-for-word accuracy/completeness is introduced.
- agent-decided — preserve validated language/source information through extraction and include the subtitle language and human/automatic source in newly saved video content. Preserve ordinary article content formatting. Existing cached video content without sufficient validation information must be re-extracted before a pending summary can be generated, rather than trusted as an original-language transcript. Already completed summaries retain existing skip handling and are not rewritten automatically.
- agent-decided — allow subtitle/data requests only to the source platforms and their necessary media endpoints. Do not invoke Defuddle's outside aggregation/proxy fallbacks or hosted API implicitly. Source requests use existing access; no new paid service, account, credentials, or standing third-party dependency is introduced. The existing summarization provider/configuration is unchanged.
- agent-decided — social adapters must verify target identity and use the first-party page or its first-party data. Extract a Threads target post, Medium main article, or X target post/long article; do not newly crawl conversation threads, include other users' replies, or claim access to unavailable private/member-only content. Existing configured authenticated profiles and manual visible-browser login can be used; authentication is not automated and access controls are not bypassed.
- agent-decided — use the existing direct URL, batch, and watch paths; no new command/config selection is required. Preserve timeouts, source filters/order/limits, skip handling, summary output paths and copy settings. Existing article content caches still pass applicable content validation. Public fixture tests and isolated browser runs precede any optional live user-data validation; never interrupt the user's active batch.
- agent-decided — errors remain explicit through the browser and pipeline boundaries rather than being collapsed into an unexplained empty string. Error text distinguishes unavailable subtitles, unverified original language, unusable subtitles, inaccessible social content and ordinary extraction failures. This is a diagnostic distinction in existing logs and failed-item reports, not a new persistent queue or UI.

## Alternatives considered
- Enable parseAsync for every URL without request restrictions: rejected because some upstream adapters may use third-party sources and an apparently successful video result can contain only its description.
- Accept any nonempty extracted string: rejected because descriptions, previews, login pages and wrong-target text violate the confirmed correctness requirement.
- Always prefer human subtitles: rejected because the user reported empty or inferior human tracks; actual contents must be checked.
- Prefer Chinese/English or the platform default when original language is uncertain: rejected because this can silently choose translated content.
- Build an independent audio transcription or semantic subtitle-ranking service: rejected because the requested source is existing platform subtitles; it would add cost and data transfer without authorization.
- Bypass Medium subscriptions or use an outside mirror/proxy: rejected because existing legitimate access is the conservative reversible boundary.
- Automatically rewrite old notes or reprocess completed summaries: rejected because the request changes future extraction, not existing completed user data.

## Current state evidence
- Forward: cmd/rlss/url.go:runURL and cmd/rlss/process.go:runProcess create the extraction pool and process items; the watch callback shares the batch pipeline.
- Reverse: internal/pipeline/runner.go:ProcessItem calls extractWithFallback; internal/extract/pool.go:ExtractURL and ExtractURLHeaded use Browser.Extract or ExtractPaginated.
- Error: inject.ts:extractArticle catches errors and returns an empty string; internal/pipeline/extraction.go:validateExtractedContent rejects empty, blocked and unavailable text, but has no video/target-identity evidence.
- Data: inject.ts currently returns only result.content from synchronous parse; internal/extract/browser.go awaits the wrapper promise but returns a string; internal/output content assembly and internal/pipeline/runner.go resume handling currently do not establish original subtitle language.
- Boundary: package.json uses defuddle latest while the installed package and lock baseline are 0.14.0; no source-platform video track policy exists. Internal/config/config.go:ExtractConfig and internal/extract/domain.go retain browser/config semantics; existing note paths and running processes are outside this change's migration scope.

## UI flows
| Case | What the user does | What they see |
|---|---|---|
| Video success | Processes a supported YouTube or Bilibili video through the existing single-URL, batch or watch command | Saved content contains actual original-language subtitles and identifies their language and human/automatic source; ordinary summary processing follows the existing settings. The single-URL command exits 0 on success. |
| Empty human subtitles | Processes a video with empty human subtitles and usable original-language automatic subtitles | The usable automatic subtitles are saved and labeled; the empty human track does not count as success. |
| Multiple usable tracks | Processes a video with both usable original-language human and automatic subtitles | A validated original-language track is saved; no message claims human or automatic subtitles are inherently more accurate. |
| Original language unknown | Processes a video whose original-language evidence is absent or conflicting | The existing failed-item report says original language could not be verified; no substitute subtitle/content or summary is newly saved. Single-URL exits nonzero. Retry when original-language information is available. |
| No usable original track | Processes a video with no original-language subtitles, only translations, blank/timestamp-only tracks, malformed cues, explicitly incomplete responses, or inaccessible subtitle data | The existing failed-item report states unavailable or unusable original-language subtitles; no video-description-only summary is generated. Single-URL exits nonzero. Retry when usable original subtitles/access are available. |
| Other video platform | Processes a recognized video URL outside the initially supported platforms | The item reports unsupported video transcript extraction instead of saving a description as its transcript; single-URL exits nonzero. Use a supported platform copy if available. |
| Social success | Processes an accessible Threads, Medium or X/Twitter target through an existing command | The saved article contains the target main text, without other posts, recommendation lists or reply text as its body. Single-URL exits 0 on success. |
| Login, challenge or subscription | Processes a target that requires access not currently available | Existing browser-mode/profile and challenge-retry settings apply; if the target body remains inaccessible, the item is failed and no login page/preview is saved as the article. Single-URL exits nonzero. Restore legitimate access in the configured browser profile and retry. |
| Wrong or empty social content | Processes a page with missing target content, an explicit preview/truncation indicator, or a result belonging to another post/article | The item is failed with the cause in its existing log; no substitute body or summary is newly saved. Retry the correct accessible target URL. |
| In progress | Waits for a page or subtitle request | Existing item/browser progress remains; the configured extraction timeout bounds the operation. A subtitle/candidate failure can lead to another candidate or existing headed retry before the final failed-item result. |
| Batch and watch failure | Processes a batch containing an unsuccessful video/social item | That item is counted as failed rather than successful; other items continue. Existing batch/watch exit behavior and watch interval remain unchanged; a later cycle rechecks current data/access. |
| Cached incomplete video | Resumes a video whose content was previously saved but whose summary is missing | Unverified cached video text is not summarized as a verified transcript; fresh extraction is attempted and can fail with the same explicit reasons. No old file is deleted as a migration. |
| Already completed | Encounters an item with an existing completed summary | Existing skipping is preserved; this change does not silently rewrite old notes or claim that their contents were revalidated. |
| No selected items / dry run | Runs an empty batch or a dry run | Existing no-items/dry-run output is retained; no subtitle request, extraction or summary call is added. |

The user can stop and rerun through existing commands; an interrupted operation does not invent a successful transcript, and a rerun revalidates newly fetched video/social content. Existing configuration parsing, missing-file errors and output-write errors retain their normal nonzero direct-command errors. No interactive control or terminal layout is added; existing text logs and Markdown outputs continue to work in narrow or piped terminals. Browser first-party network access is required; offline extraction and guaranteed access to unavailable content are not promised. No new third-party content forwarding or audio upload is authorized. This work adds no destructive conversion of existing notes, and it does not deploy or restart the running binary automatically.
